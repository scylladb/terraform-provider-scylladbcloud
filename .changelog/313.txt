
```release-note:note
resource/scylladbcloud_vpc_peering: A GCP peering without `peer_cidr_blocks` whose `peer_region` is known only at apply time now fails at plan time. Set `peer_cidr_blocks` in such a configuration
```

```release-note:feature
resource/scylladbcloud_vpc_peering: A GCP peering is imported with its region: `<connection_id>,<peer_region>`. Without the region, the import fails with a hint. A GCP peering imported with an earlier version has an empty `peer_region` in the state, and its next plan replaces it: remove it from the state and import it again with its region, as the import example shows
```

```release-note:note
resource/scylladbcloud_vpc_peering: Without `peer_cidr_blocks`, a configuration that fails at plan time also fails `terraform destroy`, because Terraform plans the configuration to refresh the state first. Set `peer_cidr_blocks`, or run `terraform destroy -refresh=false`, which skips that plan. An empty list, `peer_cidr_blocks = []`, fails validation also with `-refresh=false`: set a nonempty list, or remove the argument when the GCP region has a default CIDR block
```
