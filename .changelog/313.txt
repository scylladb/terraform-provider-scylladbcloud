
```release-note:bug
resource/scylladbcloud_vpc_peering: A refresh checks the cluster in `cluster_id` first. A peering that another cluster also lists, as clusters that share a network do, could get the ID of that cluster on refresh, and the next plan showed a `cluster_id` change. If the cluster in `cluster_id` is gone or no longer lists the peering, but another cluster does, the refresh fails and names that cluster, instead of removing the peering from the state. To manage the peering through that cluster, remove it from the state and import it again. An import takes the first cluster that lists the peering, so when several clusters list it, check the imported `cluster_id` and the next plan before applying
```

```release-note:enhancement
resource/scylladbcloud_vpc_peering: Without `peer_cidr_blocks`, a GCP peering with a `datacenter` that the cluster does not have fails at plan time instead of during apply, when the plan knows the `datacenter` name. With `peer_cidr_blocks`, the apply still reports it
```

```release-note:note
resource/scylladbcloud_vpc_peering: A GCP peering without `peer_cidr_blocks` whose `peer_region` or `cluster_id` is known only at apply time, as for a peering on a cluster made in the same apply, now fails at plan time. Set `peer_cidr_blocks` in such a configuration
```

```release-note:feature
resource/scylladbcloud_vpc_peering: A GCP peering is imported with its region: `<connection_id>,<peer_region>`. Without the region, the import fails with a hint. A GCP peering imported with an earlier version has an empty `peer_region` in the state, and its next plan replaces it: remove it from the state and import it again with its region, as the import example shows
```

```release-note:note
resource/scylladbcloud_vpc_peering: Without `peer_cidr_blocks`, a configuration that fails at plan time also fails `terraform destroy`, because Terraform plans the configuration to refresh the state first. Set `peer_cidr_blocks`, or run `terraform destroy -refresh=false`, which skips that refresh. Terraform still plans the destroy. An empty list, `peer_cidr_blocks = []`, fails validation also with `-refresh=false`: set a nonempty list, or remove the argument when the GCP region has a default CIDR block
```
