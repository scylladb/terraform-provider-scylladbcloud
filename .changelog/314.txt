```release-note:bug
provider: Reading VPC peerings, allowlist rules and cluster connections no longer fails while the account has a cluster whose instance the API cannot report, for example while none of its nodes is ACTIVE
```

```release-note:bug
resource/scylladbcloud_vpc_peering: Reading a VPC peering no longer fails while another cluster of the account has no datacenter, for example right after it is created or after its creation failed. While the cluster of the peering itself is listed without a datacenter, its refresh, also the one before `terraform destroy`, still fails, and asks to try again
```

```release-note:bug
resource/scylladbcloud_cluster: Reading a cluster no longer fails when the API cannot report its instance. If only the instance lookup of the API fails, the read and the import work as usual. While none of the nodes of a Standard cluster is ACTIVE, the read keeps `node_type`, `node_disk_size` and `min_nodes` from the state, and an import fails until a node is ACTIVE
```

```release-note:bug
resource/scylladbcloud_cluster_connection: Importing a cluster connection no longer fails while the account has a public cluster without a datacenter, for example right after it is created
```
